FastAPI Router & Classifier Service Integration

Overview

This session introduced the core machine learning inference pipeline for the Email Classification API, bridging pre-trained scikit-learn model artifacts with FastAPI dependency injection and structured Pydantic schemas.

Key Components & Architecture

1. Pydantic Request & Response Schemas (app/api/v1/model.py)

Defines strong type validation for incoming classification requests and outgoing responses.

  • EmailRequest: Validates that payload contains non-null text: str.
  • EmailClassificationResponse: Serializes prediction output returning is_spam: bool and confidence: float (rounded to 4 decimal places).

2. Classifier Service Layer (app/services/classifier_service.py)

Encapsulates model loading, custom feature extraction, and prediction logic.

  • _load_artifacts(): Safely loads spam_model.pkl and feature_names.pkl via joblib during service initialization. Raises FileNotFoundError if artifacts are missing.
  • extract_features(text: str): Uses regular expressions (re.findall(r"\b[a-zA-Z0-9]+\b", text.lower())) and Counter to calculate word frequencies, aligning them strictly with self.feature_names in a single-row pandas.DataFrame.
  • classify(text: str): Invokes predict() and predict_proba() on the model, extracting class probability confidence score.
  • get_classifier_service(): Module-level global singleton provider function used for dependency injection.

3. FastAPI APIRouter (app/api/v1/classifier_api.py)

Exposes the HTTP POST endpoint /api/v1/classify.

  • Uses Depends(get_classifier_service) to inject the singleton service instance into the endpoint handler without tight coupling.

4. Lifespan Pre-warming (main.py)

Uses an asynccontextmanager lifespan handler to invoke get_classifier_service() during FastAPI application startup, ensuring model artifacts are loaded in memory prior to serving traffic.

# Service Feature Extraction Logic
def extract_features(self, text: str) -> pd.DataFrame:
    words = re.findall(r"\b[a-zA-Z0-9]+\b", text.lower())
    word_counts = Counter(words)
    features_dict = {word: [word_counts.get(word, 0)] for word in self.feature_names}
    return pd.DataFrame(features_dict)
# FastAPI Endpoint with Dependency Injection
@router.post("/classify", response_model=EmailClassificationResponse)
def classify_email(
    payload: EmailRequest,
    service: ClassifierService = Depends(get_classifier_service),
) -> EmailClassificationResponse:
    return service.classify(payload.text)

1. What is the primary purpose of get_classifier_service() in app/services/classifier_service.py?
Explanation: get_classifier_service() maintains a module-level global variable _classifier_service. If it is None, it instantiates the service once and reuses that instance for subsequent dependency injection calls.
2. How does ClassifierService.extract_features() transform raw email text for model prediction?
Explanation: extract_features uses re.findall(r"\b[a-zA-Z0-9]+\b", text.lower()) and Counter(words) to build a single-row dictionary for all expected feature names before passing it to pd.DataFrame().
3. How does the endpoint handler in app/api/v1/classifier_api.py receive the service instance?
Explanation: FastAPI's Depends() mechanism handles injecting the singleton returned by get_classifier_service() directly into the function parameter.
4. What mechanism in main.py pre-warms model artifacts during server startup?
Explanation: FastAPI's lifespan context manager runs code before the server yields to start receiving HTTP requests, ensuring `get_classifier_service()` loads the model beforehand.
5. How is the confidence score determined in ClassifierService.classify()?
Explanation: model.predict_proba() returns predicted probabilities for each class. The service retrieves the probability matching prediction_int to represent model confidence.
6. What Pydantic response model is returned by the /api/v1/classify endpoint?
Explanation: EmailClassificationResponse in app/api/v1/model.py specifies is_spam (boolean) and confidence (float).
7. Why are model .pkl files loaded into memory once during application startup rather than inside every API request?
Explanation: Reading model artifacts from disk on every request is extremely slow and inefficient. Loading artifacts into memory once at startup ensures high-performance, low-latency API response times.
